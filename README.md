# Nバック課題アプリ — 第1段階

仕様書は [nback-spec.md](nback-spec.md)。この README は実装側の話だけ。

## 動かす

`index.html` を開くだけ。ビルドもサーバも要らない。

ローカルで確認するとき:

```bash
python -m http.server 8123
```

## スマホで使う（GitHub Pages）

1. github.com で `nback` という名前のリポジトリを新規作成（README などは追加しない）
2. このフォルダで `git remote add origin https://github.com/USERNAME/nback.git`
3. `git push -u origin main`
4. リポジトリの Settings → Pages → Source を「Deploy from a branch」、Branch を `main` / `(root)` にして Save
5. `https://USERNAME.github.io/nback/` を開き、共有メニューから「ホーム画面に追加」

ファイル参照はすべて相対パスなので、サブディレクトリ配信でもそのまま動く。

**https で配信すること。** Wake Lock（課題中に画面を消させない）と Service Worker は
保護されたコンテキストでしか動かないので、LAN の平文 http で配ると両方とも無効になる。

### ホーム画面とオフライン

- `manifest.webmanifest` — Android Chrome が独立したアプリとして扱うために要る。
  iOS は `apple-mobile-web-app-capable` のメタタグだけで全画面になる
- `icons/` — 3×3グリッドの1マスが光っている図。作り直すなら `python tools/make-icons.py`
  （PNG を直接書き出すので Pillow は要らない）
- `sw.js` — 一式をキャッシュして、電波がなくても起動できるようにする

**ファイルを更新したら `sw.js` の `VERSION` を1つ上げること。**
ブラウザは `sw.js` の中身が変わったときだけ更新処理を始めるので、
ここが同じままだと古いキャッシュが配られ続ける。
更新は「次に開いたとき」に反映される（課題の途中で差し替わらないようにしてある）。

## 着手前に決めたこと（仕様書の3項目）

1. **動作環境** — ブラウザ単体（HTML/JS、依存ライブラリなし）。GitHub Pages に置いてスマホから使う
2. **音声の出し方** — 第2段階では事前録音した音声ファイルを使う。Web Speech API は使わない。
   `js/modalities.js` に `audio-letter` を1つ登録すれば載る作りにしてある
3. **保存先** — ブラウザ内 localStorage。中身は仕様書どおり1行1ブロックの形なので、
   `.jsonl` として書き出し／読み込みできる（端末を移すときはこれを使う）

## 応答方式

2つある。設定画面で切り替える。

### リアルタイム判定（no-go）

仕様書どおり。提示中に、N個前と一致したらボタンかスペースキーを押す。一致しないときは押さない。
ヒット / ミス / 誤警報 / 正棄却 の4分類で記録し、**ヒット率と誤警報率を必ず別々に**持つ。d′ も出す。

### 提示後に入力（記憶スパン）

**問題数を決める → その数だけ順に提示される → 全部出たあと、出てきた順に思い出して入力する。**
10問と決めたら10個出て、10問答える。

Nバックではないので **N は使わない**（設定画面では N・ターゲット率・ひっかけを隠す）。
難易度は問題数そのもの。列は `core.generateSequence` に `n: 0` を渡して作る
（Nバック構造もターゲットも作らず、直前と同じ記号だけ避けた乱数列）。

記録は 正答率 / 誤答数 / 連続正答数 / 平均反応時間。ヒット率・誤警報率・d′ は `null`、`n` は `0` になる。
結果画面には1問ずつ「正解 → 自分の回答」を並べて、どこで崩れたかを出す。

## モダリティ

| id | 内容 | 入力 |
|---|---|---|
| `visual-number` | 1〜9の数字を中央に表示 | 数字パッド（キー: 1〜9） |
| `visual-position` | 3×3グリッドのマスが光る。中央を除いた8マス | マスをタップ（キー: 1〜9 が読み順のマス） |
| `mixed-number-position` | 試行ごとに数字か位置かが切り替わる | 位置パッドと数字パッドを並べる |

（入力パッドは「提示後に入力」方式で使う。リアルタイム判定では一致ボタン1つだけ。）

混合モードの記号は `N5`（数字の5）と `P3`（位置の3）の2種類。一致は**種類と値の両方**が同じときだけ。
数字はグリッドの中央に出す（中央マスは位置刺激には使わないので取り違えない）。
入力ではどちらのパッドを押したかで種類も同時に決まるので、1タップで答えられる。
キーは数字が 1〜9、位置が Q W E / A S D / Z X C。

## 構成

刺激列の生成と提示・入力を分離してある。モダリティは設定値で、分岐ではない。

| ファイル | 役割 | DOM |
|---|---|---|
| `js/core.js` | 刺激列の生成、2方式の判定、d′、難易度の目安 | 触らない |
| `js/modalities.js` | 提示方法と入力方法の登録 | 触る |
| `js/runner.js` | 1ブロックを回す。チャンネルの配列を受け取る | 触る |
| `js/storage.js` | localStorage と JSON Lines | — |
| `js/history.js` | 履歴の集計とグラフ | 触る |
| `js/app.js` | 画面の組み立てと進行 | 触る |
| `sw.js` | オフライン用のキャッシュ | — |
| `manifest.webmanifest` | ホーム画面に追加したときの見え方 | — |

`core.js` はモダリティを知らない。記号の配列を受け取って記号の列を返すだけで、
それが数字なのかマスの位置なのか、数字と位置の混合なのか、読み上げる文字なのかには関与しない。

## 第2段階を足すとき

**音（audio-letter）** — `js/modalities.js` に1つ足す。判定側は触らない。

```js
M['audio-letter'] = {
  id: 'audio-letter', label: '音声 (子音)', kind: 'audio', defaultKey: 'L',
  alphabet: () => ['C','H','K','L','Q','R','S','T'],
  format: s => s,
  mount: () => ({ audio: new Audio() }),
  show: (h, sym) => { h.audio.src = 'audio/' + sym + '.mp3'; h.audio.play(); },
  hide: () => {},
  unmount: () => {},
  mountInput: (c, settings, onPick) => { /* 8個の文字ボタン */ }
};
```

そのうえで `app.js` の `buildSetup()` にある `.filter(m => m.kind === 'visual')` を外す。

**デュアル** — `app.js` の `buildConfig()` で `channels` を2要素にするだけ。

```js
channels: [
  { modalityId: 'visual-position', key: 'A' },
  { modalityId: 'audio-letter',    key: 'L' }
]
```

`runner.js` はすでにチャンネルごとに独立した列を作り、独立に判定している。
リアルタイム方式なら反応ボタンがチャンネル数だけ並び、提示後入力方式なら入力パッドが並ぶ。
記録も `record.channels[]` に per-channel で入る（単一のときは先頭が
トップレベルにも出るので、履歴画面の集計はチャンネル数に依存しない）。

**適応的難易度** — `core.suggestNextN()`（リアルタイム / Jaeggi の 3・5 規則）と
`core.suggestNextTrials()`（提示後入力 / 問題数の増減）が既にある。今は結果画面に目安を出すだけ。

## d′ について

対数線形補正つき。0%/100% でも無限大にならない代わりに、
ターゲット数と非ターゲット数が違う（6 対 16 など）ため、全押しでもちょうど 0 にはならず ±0.4 程度に出る。
これは補正の性質で、弁別できていないことは読み取れる。

## 記録の形

1行1ブロックの JSON Lines。`responseMode` で方式が分かれる。

- `realtime`: `n` は1以上。`hits` / `misses` / `falseAlarms` / `correctRejections` / `hitRate` / `faRate` / `dPrime`
- `recall`: `n` は 0。`questions` / `correct` / `incorrect` / `accuracy` / `streak`

`version: 1` の記録には `responseMode` がないが、当時はリアルタイム判定しかなかったので
履歴側でそう解釈している。履歴の表は `n` が 0 の行を「—」にし、N の推移グラフからも外す。

## テスト

```bash
node test/core.test.js
```

刺激列の再現性、ターゲット率、lure の混入、ヒット/ミス/誤警報/正棄却、d′、
Nバック構造を作らない列 (n = 0)、提示後入力の集計、混合モダリティの記号列、難易度の目安を確認する。

## 操作

- リアルタイム方式: 画面下のボタンをタップ、またはスペースキー。一致しないときは押さない
- 提示後入力方式: 提示中は見るだけ。全部出たあとパッドをタップ、またはキー。押し間違えたら「1つ戻る」（Backspace）
- 同一試行内の二重押しは無視
- ブロック中の中止 = 中止ボタン または Esc（記録は残らない）
- 履歴の「再挑戦」= 同じシードと設定で同じ列をもう一度
- ブロック中は Wake Lock で画面を消灯させない（対応ブラウザのみ）
